# @toolpack-sdk/agents v3.5.0

Date: 2026-10-11

## Highlights

- **Stopping a run takes effect at once**: in the middle of a model call or a tool, not only between tool rounds
- **`metadata.aborted`**: a stopped streaming run returns the text that had arrived and says it was stopped
- **Agent Mind**: a stopped run does not record its goal writes

---

## New features

### A stopped run reports that it was stopped

Passing `signal` to `invokeAgent()` or `run()` works as before, and the stop now takes effect at once (see the `toolpack-sdk` notes). What the caller gets back depends on whether the run streams:

| Run | On a stop |
|---|---|
| Streaming (`onChunk` set, or the mode has `streaming`) | Resolves with the text that had arrived, and `result.metadata.aborted` is `true` |
| Not streaming | Rejects with an error whose `name` is `'AbortError'`. `onError` and `agent:error` fire as for any failed run |

```typescript
const controller = new AbortController();

const result = await agent.invokeAgent({
  message: 'Write a long report',
  signal: controller.signal,
  onChunk: (delta) => process.stdout.write(delta),
});

if (result.metadata?.aborted) {
  // result.output is the part that arrived before the stop
}
```

### Agent Mind on a stopped run

A stopped streaming run is saved like a failed one: beliefs and reflections from the run are kept, and its goal writes are dropped. A run that was cut off should not record goals as done.

---

## Behaviour changes

- A run that does not stream now rejects with an `AbortError` when its signal is aborted. Before, it returned the last response
- A stop is seen in the middle of a model call or a tool, not only between tool rounds. Sub-agents reached through `delegate_to_agent` receive the same signal

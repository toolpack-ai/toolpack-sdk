# @toolpack-sdk/agents v3.2.0

Date: 2026-09-06

## Highlights

- **File attachments in agents** — `AgentInput.attachments` accepts `FilePart` and `ImagePart`; all built-in agents forward attachments through `invokeAgent`
- **`ChatChannel`** — new externally-driven channel for in-app or HTTP-server use cases
- **Attachment validation** — `BaseChannel.validateAttachments()` enforces `FILE_LIMITS` inside `normalize()`
- **Mind tools via `loadRequestToolProject`** — mind tools are now registered as a `ToolProject` that bypasses mode filtering, removing the per-request `requestTools` array from `BaseAgent`

---

## Breaking changes

| Change | Migration |
|---|---|
| `RunContext.tools: RequestToolDefinition[]` removed | `RunContext` now exposes `toolProject: ToolProject`; consumed automatically by `BaseAgent` — only affects custom `AgentMind` consumers |

## New features

### `AgentInput.attachments`

All agents now accept image and file attachments alongside the message:

```typescript
const result = await agent.invokeAgent({
  message: 'Review this contract',
  attachments: [{
    type: 'file',
    file: { url: 'https://example.com/contract.pdf', mimeType: 'application/pdf' },
  }],
  conversationId: 'conv-123',
});
```

`BaseAgent.run()` builds a multipart user message when attachments are present. Built-in agents (CodingAgent, ResearchAgent, DataAgent, BrowserAgent, EphemeralAgent) all forward `input.attachments` automatically.

---

### `ChatChannel`

A non-trigger channel driven directly by your HTTP server or framework. `listen()` and `send()` are no-ops — the caller drives the agent by calling `agent.invokeAgent()` directly.

```typescript
import { BaseAgent, ChatChannel } from '@toolpack-sdk/agents';

class MyAgent extends BaseAgent {
  name = 'my-agent';
  channels = [new ChatChannel({ name: 'chat' })];

  async invokeAgent(input) {
    return this.run(input.message, undefined, { conversationId: input.conversationId }, input.attachments);
  }
}

const agent = new MyAgent({ toolpack });
await agent.start();

// In your HTTP handler:
const result = await agent.invokeAgent({
  message: req.body.message,
  attachments: req.body.attachments,
  conversationId: req.body.conversationId,
  participant: { id: req.body.userId },
});
```

`ChatChannel.normalize()` parses the request body and populates `message`, `attachments`, `conversationId`, and `participant`. It sets `context.source = 'chat'`.

| Field | Type | Description |
|---|---|---|
| `name` | `string` (optional) | Channel name for routing |
| `isTriggerChannel` | `false` | Never starts a polling loop |

---

### `BaseChannel.validateAttachments()`

Protected helper for channel implementations. For `FilePart`, picks `FILE_LIMITS.image.maxBytes` or `FILE_LIMITS.document.maxBytes` based on MIME type, and only checks when `size` is supplied. For inline `image_data`, the limit is always checked via a base64-length estimate (base64 length × 0.75). Throws a descriptive error if a limit is exceeded. `image_url` and `image_file` parts are skipped — size is unknown on the server side.

Channels that accept attachments should call this inside their `normalize()` method. `ChatChannel` does this automatically.

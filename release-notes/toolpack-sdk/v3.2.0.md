# Toolpack SDK v3.2.0

Date: 2026-09-06

## Highlights

- **File attachments** — new `FilePart` type and `FILE_LIMITS` constant let you attach documents (PDFs, etc.) alongside messages; all five providers updated
- **`registerRequestTools` / `loadRequestToolProject`** — public methods to register tools that bypass mode filtering entirely
- **Skill interceptor removed** — `createSkillInterceptor`, `SkillInterceptorOptions`, and `skillInterceptor` mode flag are gone; use `createSkillTools` instead
- **Improved knowledge and mind tool guidance** — `AIClient` now generates richer in-prompt instructions that differentiate personal user memory (`mind_believe`) from shared knowledge (`knowledge_add`)

---

## Breaking changes

| Change | Migration |
|---|---|
| `createSkillInterceptor` removed | Delete the interceptor from your `Toolpack.init()` config; wire `createSkillTools` into `ModeConfig.customTools` if you want LLM-managed skills |
| `SkillInterceptorOptions` type removed | No replacement needed |
| `skillInterceptor?: boolean` removed from `ModeConfig` | Remove the field from any custom mode definitions |
| `RunContext.tools` removed from `AgentMind` (internal) | Mind tools are now registered via `toolpack.loadRequestToolProject(runCtx.toolProject)` — no change needed if you use `BaseAgent` |

## New features

### `FilePart` and `FILE_LIMITS`

Attach non-image files (PDFs, spreadsheets, etc.) to any message using a public URL or data URI:

```typescript
import { FilePart, FILE_LIMITS } from 'toolpack-sdk';

const doc: FilePart = {
  type: 'file',
  file: {
    url: 'https://example.com/report.pdf',
    mimeType: 'application/pdf',
    name: 'report.pdf',   // optional, display only
    size: 204800,         // optional bytes, used for client-side limit checks
  },
};

const response = await toolpack.generate({
  messages: [{ role: 'user', content: [{ type: 'text', text: 'Summarise this' }, doc] }],
  model: 'claude-sonnet-5',
});

// FILE_LIMITS.image.maxBytes    → 10 MB
// FILE_LIMITS.document.maxBytes → 10 MB
// FILE_LIMITS.document.maxPages → 20 pages
```

`FilePart` is included in the `MessageContent` union. A data URI (`data:<mime>;base64,<data>`) is also accepted in `file.url` for inline embedding.

#### Provider support

| Provider | URL | Inline base64 (`data:` URI) |
|---|---|---|
| **Anthropic** | images and documents | auto-routed to `image` or `document` block |
| **Anthropic Vertex** | images and documents | auto-routed to `image` or `document` block |
| **Gemini** | `fileData` | `inlineData` |
| **VertexAI** | `fileData` | `inlineData` |
| **OpenAI** | images and documents | Images only (non-image base64 is dropped) |

### `registerRequestTools()` and `loadRequestToolProject()`

Register tools that bypass mode filtering and are always passed to the model regardless of `allowedToolCategories`. This is the same mechanism used internally by knowledge and mind tools.

```typescript
import { RequestToolDefinition } from 'toolpack-sdk';

// From a ToolProject:
toolpack.loadRequestToolProject(myProject);

// From raw definitions:
const tools: RequestToolDefinition[] = [{ name: 'my_tool', ... }];
toolpack.registerRequestTools(tools);
```

Tools are deduplicated by name — registering the same name twice replaces the existing entry. Knowledge tools are now registered this way at `Toolpack.init()` time rather than rebuilt on every request.

### Improved knowledge and mind tool instructions

When both `knowledge_add` and `mind_believe` are available, `AIClient` now generates distinct guidance:

- `knowledge_search` — instructs the model to search proactively before concluding it does not know something
- `knowledge_add` — scoped to factual domain knowledge (documents, research, organizational data); not for personal user facts
- `mind_believe` — explicitly preferred for personal user facts and preferences
- `mind_reflect` — for lessons learned and standing rules
- `mind_recall` — for searching personal memory before answering questions about the user

## Removed

### `createSkillInterceptor`

`createSkillInterceptor` performed BM25 search on every user message and auto-injected matching skill instructions. It is removed in this release.

**Before:**

```typescript
import { Toolpack, createSkillInterceptor } from 'toolpack-sdk';

const toolpack = await Toolpack.init({
  provider: 'anthropic',
  interceptors: [
    createSkillInterceptor({ dir: '.toolpack/skills', maxSkills: 3, minScore: 0.3 }),
  ],
});
```

**After:** use `createSkillTools` — the agent calls `skill.read` explicitly when it needs instructions:

```typescript
import { createSkillTools } from 'toolpack-sdk';

const skillTools = createSkillTools({ dir: '.toolpack/skills' });
// agent.mode = { ...agentMode, customTools: [...skillTools.tools] };
```
